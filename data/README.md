# Data README

## 1. Dataset identity
- **Dataset name:** Telco Customer Churn (IBM sample dataset)
- **Source URL / owner:** IBM, mirrored at
  `https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv`
- **Accessed on:** 2026-07-31
- **Usage / license conditions:** Publicly available sample dataset distributed by IBM for
  educational/demo use. Not licensed for redistribution as a commercial product; safe for this
  coursework capstone.
- **How to obtain the data:** A committed copy lives at `data/Telco-Customer-Churn.csv` in this
  repository. If that file is ever missing, `demo.ipynb`'s data-loading cell automatically falls
  back to the public URL above — no manual download needed either way.

## 2. What the data represents
- **One row/example represents:** one bank/telecom customer account snapshot at a point in time.
- **Target or unsupervised objective:** `Churn` — binary (Yes/No), whether that customer has left
  the service.
- **Prediction or evaluation moment:** at the time of the snapshot, using account, service, and
  billing attributes that would be known *before* any future churn outcome — no post-outcome
  fields are used as inputs.
- **Primary group/time fields:** `customerID` (unique per row; excluded from modeling features —
  see `docs/data_audit.md` leakage controls). No repeated-customer-over-time structure: this is a
  single snapshot per customer, not a longitudinal panel, so no time/group-aware split is required.

## 3. Files and paths
| File/path | Purpose | Committed to Git? |
|---|---|---|
| `data/Telco-Customer-Churn.csv` | Raw source data (7,043 rows × 21 columns) | Yes |
| `demo.ipynb` | Notebook that builds the model-ready data from raw (cleaning, split, preprocessing pipeline) | Yes |
| `models/churn_model.joblib` | Saved final pipeline (preprocessing + classifier) | No — regenerated by running the notebook |

## 4. Known limitations
- Single historical snapshot from one provider — not necessarily representative of all
  telecom/banking customer populations or of churn behavior over time.
- No temporal dimension: cannot capture drift in churn drivers over time.
- Demographic fields (`gender`, `SeniorCitizen`, `Partner`, `Dependents`) are present; see the
  Responsible AI section of the main `README.md` for the fairness discussion tied to these fields.
- No direct personal-identifying information beyond `customerID`, which is excluded from
  modeling.

## 5. Reproduction notes
1. Clone this repository (the CSV is already committed under `data/`, no separate download step).
2. Install dependencies: `pip install -r requirements.txt`.
3. Open `demo.ipynb` in Google Colab and run all cells top to bottom — this rebuilds the cleaned,
   split, and preprocessed data and re-trains/re-evaluates the final model from raw data only.
